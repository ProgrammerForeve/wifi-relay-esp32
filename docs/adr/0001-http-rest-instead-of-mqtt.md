# ADR-0001: HTTP REST вместо MQTT

## Статус
Принято.

## Контекст
Устройству нужен канал управления «включить/выключить» и чтения состояния.
Классические варианты для ESP32: встроенный HTTP-сервер (esp_http_server) или
MQTT-клиент (mqtt_client) с внешним брокером. Проект учебный; на защите нужно
показать работу внешнему наблюдателю без разворачивания инфраструктуры.

## Решение
Единственный транспорт управления — HTTP REST поверх esp_http_server.
MQTT не реализуется.

Поверхность API:
- GET  /api/relay   — текущее состояние
- PUT  /api/relay   — установка состояния, тело {"state":"on"|"off"}
- GET  /api/status  — диагностика (см. ADR-0002)
- POST /api/provision — только в AP-режиме (см. ADR-0006)

Версионирование (/api/v1/) не вводится: API считается учебным и не гарантирует
обратную совместимость. Это осознанное ограничение, а не недосмотр.

## Альтернативы
- MQTT: требует брокера, добавляет ещё один компонент и точку отказа; на защите
  демонстрация усложняется (нужен брокер и клиент).
- HTTP + MQTT: вдвое больше кода и тестового покрытия без выигрыша для учебной цели.
- CoAP: экзотика, документации меньше, выигрыш не очевиден.

## Последствия
+ Демонстрация через curl или браузер, без внешней инфраструктуры.
+ Один компонент вместо двух.
− Нет push-уведомлений о смене состояния: клиент узнаёт состояние только запросом.
− Интеграция с Home Assistant потребует дополнительной работы (вне области, см. ADR-0009).
