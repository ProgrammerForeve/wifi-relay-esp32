# ADR-0004: STA с fallback в AP

## Статус
Принято.

## Контекст
Устройство должно подключаться к домашней сети (STA), но при первом включении
или после смены пароля роутера не иметь сохранённых креденшелов. Без резервного
режима устройство превращается в «кирпич».

## Решение
1. При старте — попытка подключения в STA с креденшелами из NVS.
2. Таймаут подключения — 30 с. При неудаче — переход в AP.
3. Режим AP: SSID `ESP32-Relay-XXXX` (последние байты MAC), WPA2,
   пароль из Kconfig.
4. Обрыв связи в STA: переподключение с экспоненциальной задержкой
   (1→2→4→8→…→60 с, сброс счётчика при успехе). Каждая попытка — лог WARN
   с тегом wifi_mgr.
5. После ~5 минут непрерывных неудач — переход в AP (даже если креденшелы есть).
6. Реле при всех переходах сохраняет текущее логическое состояние; переходы
   Wi-Fi на состояние не влияют.

## Альтернативы
- Только STA: устройство недоступно после смены пароля роутера.
- Только AP: ограниченная дальность, ручное переключение клиента, не «умный дом».
- APSTA постоянно: лишний расход, два IP, усложнение логики без выигрыша.

## Последствия
+ Устройство всегда доступно для перенастройки.
− Смена пароля AP требует пересборки (Kconfig).
− Возможен «флаппинг» режимов при пограничном сигнале; сглаживается backoff'ом.
