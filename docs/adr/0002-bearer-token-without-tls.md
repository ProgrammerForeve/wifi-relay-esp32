# ADR-0002: Bearer-токен без TLS, токен в Kconfig

## Статус
Принято.

## Контекст
Управляющие эндпоинты доступны по сети. Полноценный TLS на ESP32 требует
сертификатов, увеличивает бинарь и усложняет отладку; для учебного стенда
в изолированной сети ценность TLS несоизмерима с ценой.

## Решение
Аутентификация — заголовок `Authorization: Bearer <token>`.
Токен задаётся через Kconfig (CONFIG_RELAY_API_TOKEN), меняется пересборкой.

Матрица доступа:
| Эндпоинт            | Токен |
|---------------------|-------|
| PUT /api/relay      | обязателен |
| GET /api/relay      | обязателен |
| GET /api/status     | НЕ требуется (read-only диагностика) |
| POST /api/provision | НЕ требуется (только AP-режим, см. ADR-0006) |
| статика captive-страницы | НЕ требуется |

GET /api/status отдаёт: режим Wi-Fi, IP, RSSI, uptime, логическое состояние реле.
НЕ отдаёт: токен, Wi-Fi-пароль. SSID — только в AP-режиме (он и так виден
при сканировании). Обоснование: диагностика без секретов — стандартная практика,
а отсутствие токена делает демонстрацию и отладку проще.

Жёсткое правило: токен и Wi-Fi-пароль не логируются никогда, ни на каком уровне
(см. ADR-0009 и соглашение о логировании).

## Альтернативы
- Без аутентификации: не переносится на реальные сценарии, плохо на защите.
- HTTP Basic Auth: тот же уровень защиты, но хуже сочетается с curl-примерами
  и требует base64-обвязки.
- TLS с самоподписанным сертификатом: вне области работ по цене/выгоде.

## Последствия
+ Дёшево по ресурсам, просто проверяется curl'ом.
− Токен передаётся в открытом виде: перехват в сети возможен. Осознанно принято
  для изолированной лабораторной сети.
− Смена токена требует пересборки (не NVS).
