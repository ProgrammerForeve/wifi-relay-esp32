# ADR-0009: Автотестов нет, ручной smoke-тест как Definition of Done

## Статус
Принято.

## Контекст
В ESP-IDF есть Unity и возможность host-based тестов чистой логики
(валидация тела запроса, антидребезг). Автотесты дают защиту от регрессий,
но требуют времени на инфраструктуру сборки и поддержку.

## Решение
Автотесты не пишутся. Проверка — ручной smoke-тест по чек-листу, результаты
фиксируются в отчёте.

Чек-лист (минимум):
1. Первое включение без креденшелов → AP через 30 с, captive-страница открывается.
2. Provisioning: ввод SSID/пароля → устройство уходит в STA, IP виден в /api/status.
3. GET /api/relay с токеном → 200 и корректное состояние.
4. PUT /api/relay {"state":"on"} → реле щёлкает, повторный GET подтверждает.
5. PUT /api/relay без токена / с неверным токеном → 401.
6. PUT /api/relay с невалидным телом → 400 и JSON {"error":"..."}.
7. Короткое нажатие кнопки → toggle; дребезг не даёт двойных срабатываний.
8. Долгое нажатие 5 с → запись Wi-Fi в NVS стёрта, устройство в AP.
9. Обрыв Wi-Fi (выключить роутер) → backoff в логах, через ~5 мин AP.
10. Перезагрузка → реле OFF (ADR-0008), креденшелы сохранены.

Функции, которые остаются без тестов, но обязаны быть выделены в отдельные
чистые функции (чтобы тесты можно было добавить позже без рефакторинга):
- валидация тела PUT /api/relay;
- антидребезг как функция от последовательности отметок времени (50 мс).

## Альтернативы
- Unity host-based на чистую логику: полезно, но отложено. Это осознанный долг,
  а не «не успели».

## Последствия
+ Экономия времени на инфраструктуре.
+ Definition of Done проверяем и воспроизводим.
− Регрессии ловятся только вручную и только при полном прохождении чек-листа.
− Долг зафиксирован: при появлении CI или расширении проекта — новый ADR,
  заменяющий этот.
