# AGENTS.md

Инструкции для AI-агентов, работающих с этим репозиторием.

## Что это за проект

Учебный Wi-Fi-реле на ESP32. ESP-IDF v5.x, сборка на Ubuntu.
Управление — HTTP REST. Один канал реле, одна физическая кнопка.
Архитектурные решения зафиксированы в `docs/adr/` (ADR-0001…0009);
термины — в `GLOSSARY.md`. **ADR и глоссарий первичны по отношению к коду.**
Если код расходится с ADR — прав код, а не ADR; но менять ADR можно только
через новый ADR, заменяющий старый (см. «Работа с решениями»).

## Сборка и прошивка

```bash
. $HOME/esp/esp-idf/export.sh
idf.py set-target esp32
idf.py menuconfig      # CONFIG_RELAY_API_TOKEN, CONFIG_RELAY_AP_PASSWORD
idf.py build
idf.py flash monitor
```

Автотестов нет (ADR-0009). Проверка — ручной smoke-тест по чек-листу
из ADR-0009. `idf.py build` должен проходить без warnings при каждом коммите.

## Структура

```
main/                     точка входа, инициализация компонентов
components/relay/         логика реле, мьютекс состояния (ADR-0007)
components/wifi_mgr/      STA + AP fallback, backoff, provisioning (ADR-0004)
components/http_api/      esp_http_server, обработчики, captive portal (ADR-0006)
components/button/        антидребезг, короткое/длинное нажатие
docs/adr/                 ADR-0001…0009
.scratch/esp32-relay/issues/  тикеты вертикальных срезов
GLOSSARY.md               термины проекта
```

Границы компонентов не размывать: логика реле — только в `relay`, работа
с Wi-Fi и NVS для креденшелов — только в `wifi_mgr`, HTTP-обработчики — только
в `http_api`. Кнопка не дёргает GPIO реле напрямую, а вызывает интерфейс
`relay` (иначе мьютекс из ADR-0007 не сработает).

## Чего НЕ делать

Это осознанно исключено из области работ. Не добавлять, даже если «полезно»:

- **MQTT, Home Assistant, WebSocket push** — ADR-0001. Транспорт только HTTP REST.
- **TLS, HTTPS, самоподписанные сертификаты** — ADR-0002. Только Bearer-токен по HTTP.
- **OTA-обновление** — ADR-0003. Только USB-прошивка.
- **Восстановление состояния реле из NVS** — ADR-0008. При старте всегда OFF.
- **Автотесты (Unity, host-based, CI)** — ADR-0009. Ручной smoke-тест.
  При этом чистые функции (валидация тела, антидребезг) выделять всё равно нужно —
  это долг на будущее, зафиксированный в ADR-0009.
- **Версионирование API (`/api/v1/`)** — ADR-0001.
- **Второй канал реле** — ADR-0005. Архитектура допускает, но не реализуется.
- **LittleFS/SPIFFS для страницы** — ADR-0006. Страница встроена строкой.
- **Смена токена из веб-интерфейса** — ADR-0002. Только Kconfig.
- **Очередь команд и задача-владелец реле** — ADR-0007. Только LWW + мьютекс.
  Если появится реальная потребность (таймеры, расписания) — сначала новый ADR,
  заменяющий ADR-0007.

Если задача требует чего-то из списка — остановиться и спросить, а не решать
самостоятельно.

## Правила, которые легко нарушить случайно

- **Токен и Wi-Fi-пароль не логируются никогда**, ни на каком уровне, ни в
  каком ответе. Это включает `ESP_LOGD`, отладочные `printf` и содержимое
  `GET /api/status`.
- **`GET /api/status` — без токена** (ADR-0002). Остальные управляющие
  эндпоинты — с токеном. `POST /api/provision` — без токена, только в AP.
- **Логическое состояние — источник истины**, а не чтение пина. Все чтения и
  записи — под мьютексом (ADR-0007).
- **Теги логирования** — по компонентам: `relay`, `wifi_mgr`, `http_api`,
  `button`. Уровень по умолчанию — `CONFIG_LOG_DEFAULT_LEVEL`.
- **Коды ответов**: `200`, `400` (невалидное тело), `401` (токен), `404`,
  `405`, `500`. Тело ошибки — JSON `{"error":"..."}`.
- **Стиль кода** — `idf.py clang-format` (или `clang-format` с дефолтным
  `.clang-format` из ESP-IDF). Не изобретать свой стиль.
- **Имена** — английские идентификаторы, комментарии — по-русски, как в
  существующем коде. Термины — из `GLOSSARY.md` (состояние, safe state,
  provisioning, backoff, LWW).
- **GPIO** — только через `sdkconfig.defaults` и `#define`, не хардкодить
  в нескольких местах.

## Работа с тикетами

Тикеты — в `.scratch/esp32-relay/issues/`, пронумерованы и имеют `Blocked by`.
Порядок выполнения: `01 → 02 → 03 → {04, 05} → 06`.
Не начинать тикет, пока не закрыты его блокеры. Один тикет — один
вертикальный срез: если задача не влезает в один тикет, это повод обсудить
декомпозицию, а не пихать всё в один PR.

## Работа с решениями

- Изменение архитектурного решения — только через **новый ADR**, заменяющий
  существующий. Не редактировать старый ADR задним числом.
- Новый термин или изменение значения существующего — через `GLOSSARY.md`,
  и только после соответствующего ADR (сначала ADR, потом глоссарий).
- README и тикеты могут меняться свободно, если не противоречат ADR.

## Коммиты

Conventional commits, английский, повелительное наклонение:

```
feat(relay): add mutex around state and GPIO
fix(http_api): return 400 on invalid JSON body
docs(adr): add ADR-0007 LWW with mutex
```

Тело коммита — по-русски, если нужно объяснить «почему». Заголовок — по-английски.
Один коммит — одна логическая единица. Не смешивать рефакторинг и фичу.
