# Глоссарий

Термины, по которым есть риск разойтись в понимании. При изменении решения —
сначала правится ADR, потом глоссарий.

## Канал (channel)
Физическое реле на плате. В проекте один (ADR-0005). В коде хранится так,
чтобы второй канал был локальным изменением.

## Состояние (state)
Логическое «вкл/выкл», которым оперируют API и кнопка. Источник истины —
переменная под мьютексом, а не чтение пина. Может кратковременно расходиться
с физическим положением контакта. См. ADR-0007.

## Мьютекс состояния (state mutex)
Единственный примитив синхронизации вокруг логического состояния и записи GPIO.
Все источники команд захватывают его на время «чтение — изменение — запись».
Порядок применения команд = порядок захвата. См. ADR-0007.

## Last writer wins (LWW)
Семантика разрешения конфликтов: при одновременных командах от кнопки и HTTP
побеждает применённая последней. В проекте — LWW с мьютексом (ADR-0007).

## Safe state (безопасное состояние)
Состояние реле сразу после подачи питания: всегда OFF, без восстановления
из NVS. См. ADR-0008.

## STA / AP / APSTA
Режимы Wi-Fi в ESP-IDF. STA — клиент существующей сети, AP — собственная точка
доступа, APSTA — оба. Проект: STA, при неудаче — AP. См. ADR-0004.

## Backoff
Экспоненциальная задержка переподключения к STA: 1→2→4→8→…→60 с, сброс при
успехе. После ~5 минут непрерывных неудач — переход в AP. См. ADR-0004.

## Captive portal
Режим, в котором клиент AP автоматически получает страницу настройки вместо
интернета. Требует DNS-responder, redirect и обработку probing-URL
(/generate_204, /hotspot-detect.html, /connecttest.txt). Только в AP-режиме.
См. ADR-0006.

## Provisioning
Передача устройству SSID/пароля Wi-Fi через captive portal, запись в NVS.
Отличается от «настройки» в широком смысле: только Wi-Fi-креденшелы.

## Provisioning-страница
Статическая HTML-страница в AP-режиме: форма SSID/пароль + кнопка toggle реле.
Toggle требует ручного ввода Bearer-токена. Встроена в бинарь строкой.
См. ADR-0006.

## Bearer-токен
Строка в заголовке `Authorization: Bearer <token>`. Задаётся в Kconfig,
меняется пересборкой. Не логируется никогда. См. ADR-0002.

## /api/status
Диагностический эндпоинт, доступен БЕЗ токена (read-only). Отдаёт режим Wi-Fi,
IP, RSSI, uptime, состояние реле. НЕ отдаёт токен и Wi-Fi-пароль; SSID — только
в AP-режиме. См. ADR-0002.

## NVS
Non-Volatile Storage в ESP-IDF. Хранит только Wi-Fi-креденшелы. Состояние реле
в NVS не пишется (ADR-0008).

## Kconfig
Система конфигурации ESP-IDF (`idf.py menuconfig`). Хранит токен, пароль AP
и прочие константы сборки.

## OTA
Обновление прошивки по воздуху. Вне области работ (ADR-0003).

## Smoke-тест
Ручной чек-лист проверки перед сдачей. Заменяет автотесты в этом проекте.
См. ADR-0009.

## Demo console (демо-консоль)
Расширенная captive-страница в AP-режиме: визуальная панель с индикатором
состояния реле, режимом Wi-Fi, IP, RSSI и uptime; кнопки «Обновить статус»,
«Обновить реле», toggle; форма provisioning. CSS для читаемости на проекторе.
См. ADR-0010.

## WiFi scan
Список доступных сетей, получаемый через `esp_wifi_scan_start()`. Требует
запущенного STA-интерфейса — в чистом AP-режиме недоступен, поэтому в режиме
провижининга устройство работает в APSTA. Отдаётся через `GET /api/scan`,
без токена, только AP. См. ADR-0011.

## APSTA
Режим Wi-Fi, в котором устройство одновременно клиент (STA) и точка доступа (AP).
Используется в режиме провижининга для возможности сканирования сетей.
В рабочем режиме (после provisioning) — только STA. См. ADR-0011.
